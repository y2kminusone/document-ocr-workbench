# 개발 메모와 검증 범위

## 회전 보정이 재처리에 반영되지 않는 문제

사용자가 페이지 분류 화면에서 회전을 저장했지만 재처리는 파일 객체에 있던 상태로 진행될 수 있었습니다. 페이지별 DB 회전 상태를 재처리 시 읽어 파일 객체로 전달하고, 분류 수정 시에도 해당 객체를 갱신하는 흐름을 연결했습니다. 저장과 실행이 서로 다른 상태를 볼 수 있다는 점이 핵심입니다.

관련 코드: `api_service/controllers/jobs.py`, `api_service/repositories/job_pages_repo.py`.

## 완료 표시와 결과 본문의 불일치

재처리가 끝나 사이드바가 완료 상태가 되어도 본문 결과가 갱신되지 않는 문제가 기록되어 있습니다. 이전/현재 상태의 변화, 선택한 파일과 현재 결과의 파일 ID, 결과 로딩 여부를 함께 확인하는 방식으로 결과 로드 조건을 보강했습니다.

관련 코드: `ui/public/src/api.js`의 `updateJobDetailFromPayload`.

## 표 편집 키 입력 중복

기존 DOM 테이블과 Tabulator의 키보드 핸들러가 겹치면 방향키 이동이 중복 처리되고 선택과 포커스가 어긋날 수 있었습니다. Tabulator 사용 시 기존 핸들러의 개입을 제한하고, 입력 확정 후 선택 행·열과 실제 포커스를 맞추는 코드가 남아 있습니다.

관련 코드: `ui/public/src/table_tabulator.js`, `ui/public/src/app.js`.

## 측정값을 비워 둔 이유

원본 최적화 문서에는 가상 스크롤 적용 후 예상 성능값이 적혀 있지만, 실제 연결·테스트·벤치마킹이 미완료라고도 명시되어 있습니다. 따라서 이 수치는 달성 성과로 인용하지 않습니다. 현재 테스트는 합성 데이터 기반 수정 이력 변환을 확인하며 모델 품질이나 원래 업무의 생산성 향상을 측정하지 않습니다.

추가 확인이 필요한 항목: 개인 담당 범위, 기존 처리 방식, 실제 반복 장애, 개선 전후 동일 조건의 처리시간, 검수 기준과 정확도 분모, 현업 적용 여부.
